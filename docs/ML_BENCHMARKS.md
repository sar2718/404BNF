# ML-бенчмарк: распознавание речи и диаризация

**GigaAM v3 E2E RNNT ONNX показала WER 8,7% на основном наборе и 8,0% на дополнительном.** В паре с Silero VAD + WeSpeaker CAM++ она дала наименьший общий cpWER среди сравниваемых связок: **17,3% и 26,1%** соответственно. Диаризация CAM++ была самой быстрой в обоих наборах, но точно определила число говорящих только в **2 из 7** записей.

Это прогоны команды от **5 ноября 2026 года** на ноутбуке Windows: **Intel Core i3-7020U, 8 ГБ RAM, CPU без CUDA**. Это измерения на сценарных записях, а не замеры скорости и качества Android APK. [Проверки сборки и кода](BUILD_CHECKS.md) опубликованы отдельно.

## Записи и методика

Семь записей [Veche-Bench](https://huggingface.co/datasets/artem-tish/veche-bench), всего **9 мин 45 с**, WAV PCM16 mono 16 кГц. В основном наборе четыре записи с 2–3 участниками (4 мин 12 с), в дополнительном — три совещания с 4–6 участниками (5 мин 33 с). Дополнительные совещания отличаются содержанием, но принадлежат тому же корпусу. Для каждого WAV рядом лежат CSV и JSON с эталонными репликами, говорящими и временными границами.

| Набор | Запись | Условия | Длительность, с | Говорящих |
| --- | --- | --- | ---: | ---: |
| Основной | [01_dialog_clean](../artifacts/ml-benchmarks/dataset/main/01_dialog_clean.wav) | Чистый диалог | 61,45 | 2 |
| Основной | [02_dialog_overlap](../artifacts/ml-benchmarks/dataset/main/02_dialog_overlap.wav) | Перебивания | 66,54 | 2 |
| Основной | [03_dialog_noise](../artifacts/ml-benchmarks/dataset/main/03_dialog_noise.wav) | Помехи и шум | 66,54 | 2 |
| Основной | [04_meeting_three](../artifacts/ml-benchmarks/dataset/main/04_meeting_three.wav) | Совещание втроём | 57,62 | 3 |
| Дополнительный | [P01_hr_meeting](../artifacts/ml-benchmarks/dataset/meetings/P01_hr_meeting.wav) | HR-совещание | 110,50 | 4 |
| Дополнительный | [P02_product_meeting](../artifacts/ml-benchmarks/dataset/meetings/P02_product_meeting.wav) | Обсуждение IT-продукта | 109,63 | 5 |
| Дополнительный | [P03_b2b_meeting](../artifacts/ml-benchmarks/dataset/meetings/P03_b2b_meeting.wav) | Обсуждение B2B SaaS | 112,65 | 6 |

| Метрика | Что измеряет |
| --- | --- |
| WER / CER | Ошибки текста на уровне слов / символов. Итог micro — сумма ошибок, делённая на суммарный размер эталона. |
| DER | Ошибки диаризации по времени: пропуски, ложная речь и путаница говорящих. Collar = 0, пересечения учитываются. Общий DER взят из протокола оценки по времени. |
| cpWER | Ошибки текста после оптимального сопоставления говорящих, без ограничения по времени. `UNKNOWN` может считаться отдельной группой. Итог micro взвешен по словам эталона. |
| RTF | Время вычислений / длительность записи. Например, 0,16 соответствует 9,6 с вычислений на минуту аудио. ASR и диаризация измерялись отдельно; загрузка моделей и подготовка аудио не входят в RTF диаризации. |

Чем меньше эти показатели, тем лучше. В режиме **Auto** эталонное число говорящих не передаётся. **Oracle / Fixed** используют известное число и приведены только для диагностики.

## Распознавание речи (ASR)

Сравнение на основном наборе. Whisper Tiny и Base запускались без общей нарезки, для Small сохранены оба режима. GigaAM и Small с общей нарезкой использовали короткие чанки. WER и CER исходной таблицы воспроизведены по текстам из JSONL; показатели Small без общей нарезки дополнительно рассчитаны из его сохранённого прогона.

| Модель и режим | WER | CER | RTF ASR |
| --- | ---: | ---: | ---: |
| Faster-Whisper Tiny | 38,0% | 16,7% | **0,143** |
| Faster-Whisper Base | 28,8% | 12,3% | 0,235 |
| Faster-Whisper Small, без общей нарезки | 18,5% | 9,3% | 0,629 |
| Faster-Whisper Small, с общей нарезкой | 19,1% | 9,8% | 0,831 |
| GigaAM v3 E2E RNNT ONNX | **8,7%** | **5,8%** | 0,212 |

## Диагностика и полные прогоны

| Движок | Режим и набор | Голоса | DER | cpWER | RTF |
| --- | --- | ---: | ---: | ---: | ---: |
| Pyannote | Oracle, основной | — | 12,0% | 20,8% | 1,91 |
| Sherpa | Auto 0,5, основной | — | 37,1% | 67,6% | 0,69 |
| Sherpa | Oracle, основной | — | 12,4% | 22,5% | 0,75 |
| Silero + CAM++ | Auto 0,35, чистый диалог | 10/2 | 40,4% | — | 0,147 |
| Silero + CAM++ | Fixed 2, чистый диалог | 2/2 | 16,0% | — | 0,194 |
| Silero + CAM++ | Auto 0,55, чистый диалог, кэш | 2/2 | 16,0% | 10,2% | 0,179 |
| Silero + CAM++ | Auto 0,65, чистый диалог, кэш | 2/2 | 16,0% | 10,2% | 0,179 |

Порог CAM++ **0,55** выбрали на `01_dialog_clean` после анализа 55 эмбеддингов. Для кэшированных строк RTF относится к исходному инференсу, не к повторной кластеризации. Изменение числа групп в переборе порогов само по себе не показывает изменения DER или cpWER.

В двух полных Python-прогонах GigaAM + CAM++ на том же WAV получено по **135 слов, 15 реплик и 2 говорящих**. Полное время по журналам — **30,097 с (RTF 0,490)** и **33,009 с (RTF 0,537)**. Это отдельные прогоны; их полное время нельзя сравнивать с RTF только диаризации. В [архиве результатов](../artifacts/ml-benchmarks/raw-results.zip) есть также отдельные запуски ASR и диаризации, промежуточные JSON, варианты объединения `baseline`, `conservative` и `context` и расшифровки JSON/TXT. В некоторых объединённых JSONL поле `diarization` осталось от исходного прогона; фактический вход диаризации указан в `diarization_input` или имени запуска.

## Выводы и границы проверки

- **Выбор для приложения:** GigaAM v3 E2E RNNT ONNX для ASR; Silero VAD + WeSpeaker CAM++ с порогом 0,55 для диаризации. [Текущий Android-комплект](MODELS.md) реализует эту связку. Sherpa 0,8 оставили как резерв, Pyannote Community-1 — как сравнительную модель.
- **Что ещё не подтверждено:** стабильность на длинных записях, качество на независимом корпусе живой речи и показатели на телефоне. Оценки Windows не переносятся на Android автоматически. Для vivo V25e (Helio G99, Android 14, 8 ГБ RAM) в исходном отчёте был запланирован отдельный тест: сверка FBank, эмбеддингов и интервалов, замеры RTF, пиковой RAM, нагрева и устойчивости.
- **Что можно повторить:** пересчитать WER/CER по сохранённым гипотезам и сверить micro cpWER по счётчикам в таблице. Для нового запуска выбранной связки можно использовать [текущий Python CLI](../src/ml-core/README.md) с теми же WAV. Исторические оценщики DER и cpWER и скрипты запуска всех кандидатов в архив не входили.
