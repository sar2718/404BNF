# 404BNF — M2: первая локальная GigaAM на Android

## Статус и границы

- Рабочая **Python**-модель GigaAM v3 E2E RNN-T **FP32** остаётся эталоном.
- Патч M2 запускает **три ONNX-графа** (encoder/decoder/joint) **на устройстве** через ONNX Runtime Android.
- Преобразование аудио в log-mel + RNN-T greedy decoding и оценка границ слов перенесены на Kotlin с опорой на `onnx-asr==0.12.0`.
- **Это не проверенный релиз**: полная сборка Android, фактический инференс, WER, RAM и время на vivo V25e пока не проверены. Не гарантируем ни скорость, ни совпадение слов до проверки на телефоне.
- **M1 должен быть установлен и проверен**; патч добавляется поверх M1. Диаризация, результат Transcript JSON v1, Room и пользовательский интерфейс не меняются.
- Не содержит облачного инференса, FastAPI, Python внутри Android и INT8.

## Установка

1. Создать ветку Git: `git switch -c feat/android-ml-m2` (или работать в своей ветке M1).
2. Распаковать **содержимое** патча из корня репозитория 404BNF. Появятся файлы в `src/android/ml/src/main/java/com/team404bnf/ml/asr/`, а также новый debug Activity.
3. Открыть `src/android` в Android Studio, выполнить Gradle Sync и запустить из этой папки:
   ```powershell
   .\gradlew.bat :ml:testDebugUnitTest
   .\gradlew.bat :app:assembleDebug
   ```
4. Установить debug APK на телефон. Убедиться, что в **404BNF ML Setup (debug)** модели уже установлены и SHA проверена.
5. Открыть дополнительный ярлык **404BNF ASR Test (debug)**. Нажать «Выбрать WAV и распознать локально».
6. Выбрать тестовую запись, например `01_dialog_clean.wav` из Python benchmark, предварительно скопированную на телефон.
7. После распознавания скопировать лог (текст, 40 слов с таймкодами, время) для проверки.

**Формат входа M2:** WAV PCM signed 16-bit, mono, 16000 Hz (не MP3/M4A). Это временное ограничение диагностического пути; основной AudioImportManager Эдика не меняли. Для потокового входа уже есть `GigaamAsrEngine.recognize(mono16k: FloatArray)`.

**Формат выхода M2:** `AsrOutput(text, words=[AsrWord(text, startSeconds, endSeconds)])`. Таймкоды примерные, из эмиссий RNN-T, не forced alignment. На этом этапе **нет `speaker_id`** и **нет Transcript JSON v1** — их добавим при интеграции диаризации (M3).

## Детали переноса

- Предобработка: 16 кГц, 20 ms окно (320 samples), 10 ms шаг, 320 FFT, 64 HTK log-mel коэффициента, округление Hann/mel до bfloat16 перед вычислением. Сверено с upstream `onnx-asr` 0.12.0 `GigaamPreprocessorNumpy` на синтетической записи.
- На длинных записях: quiet-point chunking 16–22 s, как в Python ML Core. Каждый чанк проходит через encoder, затем encoder закрывается, а decoder+joint загружаются после него, чтобы не держать все три сессии одновременно. Это снижает пиковую память, но **может замедлить** обработку за счёт повторной загрузки весов.
- Декодирование: greedy RNN-T, blank token определяется по словарю, максимум 3 токена на шаг encoder; сохранение state и кэш decoder output при blank.
- Точность временных меток: 0.04 s по encoder кадрам; интервал слов оценивается по эмиссиям токенов.
- FFT сейчас выполнен прямой DFT ради простоты проверки. Это **медленный прототип** (O(320²) на кадр), который потребуется ускорить, если RTF на смартфоне окажется неприемлемым.
- Для M2 отладочная запись ограничена 5 минутами; интерфейс может быть расширен после тестов памяти и стабильности.
- В случае ошибок формата или отсутствующих моделей выдаётся явная ошибка; загрузка моделей при `recognize` не запускается.

## Сравнение с эталоном

После запуска на одном и том же WAV сравнить с Python ML Core по:
- тексту и последовательности токенов (при доступности диагностики),
- списку слов и времени их начала/окончания,
- общему времени обработки и приблизительному RTF,
- памяти приложения в Android Studio Profiler.

На контрольном `01_dialog_clean.wav` Python даёт **135 слов** в итоговом совмещённом JSON; это ориентир, а не гарантия равного количества слов Android ASR.

## Коммит

Коммитить **только исходники M2**; ONNX-веса, аудиозаписи, `.venv` и пользовательские JSON в Git не добавлять. Никаких файлов Эдика в `app/src/main` патч не изменяет.
