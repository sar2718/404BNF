# 404BNF (Android-модуль)

**404BNF** — мобильное Android-приложение для записи аудио, воспроизведения и удобной интерактивной работы с расшифровками диалогов (расшифровка речи, разделение по спикерам и редактирование).

> **Внимание:** Ветка `dev/android` содержит только UI, бизнес-логику работы с аудио, базой данных (Room) и логику работы с транскрипциями (парсинг, редактирование, экспорт). Функциональность нейросетевого машинного обучения (ML) разрабатывалась в отдельной ветке и здесь отсутствует.

---

## 🚀 Назначение приложения

Приложение предназначено для записи аудиозаписей (интервью, лекций, совещаний), загрузки и визуального прослушивания структурированных расшифровок с разделением участников и временными метками, а также редактирования реплик и экспорта результатов (TXT, JSON, WAV, MP3).

---

## 🛠 Используемые технологии

- **Язык разработки:** Kotlin (Modern Android Development)
- **Пользовательский интерфейс:** Jetpack Compose, Material 3
- **Архитектура:** MVVM (ViewModel, StateFlow, Coroutines, Repository pattern)
- **База данных:** Room (SQLite)
- **Аудиоплеер:** Jetpack Media3 (ExoPlayer)
- **Запись звука:** Android `AudioRecord` + `ForegroundService` (с уведомлением и фоновой записью)
- **Сериализация:** Gson / JSON Parser
- **Кодирование аудио:** LAME (библиотека jump3r) и MediaCodec
- **Тестирование:** JUnit 4

---

## ✨ Реализованный функционал

- 🎙 **Запись аудио:** Фоновая запись звука с микрофона через `Foreground Service` (WAV PCM 16kHz Mono). Поддержка паузы и возобновления.
- 📥 **Импорт аудиофайлов:** Поддержка форматов `wav`, `mp3`, `m4a`, `aac`, `flac`, `ogg`, `opus`, `amr`, `3gp` (через Android Storage Access Framework).
- 💬 **Диалоговые расшифровки:** Загрузка (в Debug-сборке), валидация и парсинг JSON-результатов расшифровки речи. Реляционные таблицы в Room не используются, транскрипция хранится в виде JSON-снимков (`TranscriptSnapshotEntity`).
- 🧩 **Автоматическая группировка:** Интеллектуальное визуальное объединение последовательных реплик одного говорящего.
- 🔄 **Синхронизация воспроизведения:** Интерактивная подсветка текущей звучащей реплики, автоскролл.
- ✏️ **Редактирование:** Смена говорящего, изменение текста, переименование участников, скрытие реплик с возможностью восстановления.
- 💾 **Экспорт данных:** 
  - Текст: `.txt` и `.json` 
  - Аудио: `.wav` (без перекодирования) и `.mp3` (с перекодированием, 128 kbps).
- 🔒 **Приватность:** Полностью локальная обработка, автоматический бэкап данных в облако отключен (`allowBackup="false"`).

## 📂 Структура проекта

- `ui/` — Слой представления, написан полностью на Jetpack Compose (`LibraryScreen`, `PlaybackScreen`, `RecorderScreen`).
- `playback/` — Воспроизведение через ExoPlayer и кастомные экспортеры (`WavFileExporter`, `Mp3FileExporter`).
- `recording/` — Фоновый сервис записи звука и `AudioCapture`.
- `data/` — Слои Room БД, DAO и репозитории (`RecordingRepository`, `TranscriptRepository`). Хранение аудиофайлов во внутреннем хранилище `context.filesDir/recordings/`.
- `transcription/` — Управление расшифровками (форматирование, редактирование через diff патчи JSON).

## 💻 Сборка и запуск

### Открытие в Android Studio

1. Откройте Android Studio.
2. Выберите **Open** и укажите директорию `src/android/` (Например: `/home/sar/Projects/404BNF/src/android/`).
3. Дождитесь завершения Gradle Sync.

### Сборка Debug APK из терминала

Из директории `src/android/` выполните команду:
```bash
./gradlew :app:assembleDebug
```
Готовый APK-файл будет находиться по пути: `app/build/outputs/apk/debug/app-debug.apk`

### Запуск Unit-тестов
Из директории `src/android/` выполните команду:
```bash
./gradlew :app:testDebugUnitTest
```

## ⚠️ Известные ограничения
1. Транскрипция в БД хранится как `rawJson` и `userEditsJson`. Таблицы `speakers` и `utterances` существуют в схеме БД Room, но фактически не используются для хранения расшифровок.
2. Экспорт MP3 аудиозаписей, импортированных из нестандартных форматов, требует достаточного количества ресурсов устройства, так как использует `MediaCodec` декодер. Потенциально возможны `OOM` ошибки на длинных записях. 
3. На данный момент ML-транскрибация отсутствует. Для тестирования интерфейса используется Debug-функция импорта готового JSON-файла транскрипции.
